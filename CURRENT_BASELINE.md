# World Clock Widget — актуальная база между диалогами

## Обязательное решение пользователя

Актуальная локальная версия приложения на данный момент: **v1.1.134**.

Эталонный установщик:

`release\WorldClockWidget-Setup-v1.1.134.exe`

Это актуальная нативная сборка Windows на C++/Win32 + системном Microsoft WebView2. v1.1.134 собрана, штатно установлена и проверена локально. Mac-сборка для Intel и Apple Silicon, включая самопроверку скрытого будильника, прошла GitHub Actions. Windows и Mac опубликованы в релизе v1.1.134; сайт ведёт на этот релиз. Проверки на физическом Mac не было. Стандартные сочетания: Windows `Alt+Space`, macOS `Option+Space`; пользовательское сочетание Windows на этой машине — `Ctrl+/`. Автозапуск Windows использует единственную стандартную пользовательскую запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` и запускает приложение напрямую с параметром `--startup`.

## Правило для следующего диалога

1. Начинать изменения от версии, указанной в этом файле — сейчас от точного состояния `v1.1.134`.
2. Не выбирать базу по максимальному номеру установщика и не ориентироваться на обсуждения, код или QA отклонённых итераций.
3. Если локальные исходники не соответствуют указанной версии, остановиться и сначала восстановить точную базу.
4. Не считать смену номера версии восстановлением исходников.
5. После новой пользовательской правки выполнить полный workflow из `AGENTS.md`.
6. Когда новая версия собрана, установлена и проверена, в этом же цикле заменить в данном файле номер актуальной версии и путь к установщику. С этого момента все новые диалоги продолжают уже с неё.
7. Если пользователь явно просит откат, указанная им версия становится актуальной и этот файл обновляется снова.

### Предыдущий выпуск — v1.1.77

Версия `v1.1.77` собрана, штатно установлена и запущена. Telegram-синхронизация переведена на готовый общий production-сервис `https://world-clock-widget-sync.uuuraaaaa.workers.dev` и бота `@WorldClockWidgetSyncBot`: пользователю не нужны BotFather, токен, сервер, Cloudflare или chat ID. В настройках выдаётся одноразовый QR на 10 минут. После обязательных для Telegram кнопок «Запустить» и «Подключить» аккаунт привязывается, тестовое уведомление отправляется автоматически, а Windows сразу передаёт текущее состояние. Ссылка закрепляется за Telegram-пользователем после `/start`, не принимается от другого аккаунта и после успешной привязки повторно не используется.

Production backend реализован как Cloudflare Worker с SQLite Durable Object и Durable Object Alarms. Он хранит состояния, устройства, сессии, одноразовые pairing tokens, idempotency, Telegram updates и доставки; будит себя к ближайшему напоминанию и отправляет его при выключенном компьютере. При временной ошибке Telegram напоминание остаётся ожидающим и повторяется с задержками 5–300 секунд; состояние ringing выставляется только после подтверждённой доставки. Истёкшие pairing/session/idempotency/update данные очищаются, а отключение одного компьютера не разрывает остальные активные устройства аккаунта. Webhook защищён Telegram secret token, device и Mini App используют отдельные хешированные credentials, realtime работает через WebSocket без секрета в URL. Поддержаны Done, +5, +15, delete/edit, конфликт revision, очередь Windows, RU/EN команды и мобильный интерфейс. Секреты находятся только в Cloudflare. Кнопка Windows сначала открывает установленный Telegram Desktop через `tg://`, а при отсутствии обработчика автоматически использует HTTPS; QR всегда использует стандартную `t.me`-ссылку.

Пройдены py_compile, 16 основных Python-тестов, 5 тестов прежнего FastAPI backend, синтаксис JS, оба набора UI-проверок, Windows sync regression и Cloudflare core tests. Production smoke подтвердил health, наличие трёх Cloudflare secrets, выдачу credential, HTTPS и `tg://` deep links, SVG QR, TTL 600 секунд, защищённый WebSocket и отказы 401/403/404 для неверных device/admin/webhook/QR данных. Telegram `getWebhookInfo` подтвердил правильный HTTPS webhook, нулевую очередь, отсутствие ошибки и `message,callback_query`. Cloudflare deployment version: `2538d6f0-9c61-42e6-aa53-c2ea6e5f737c`.

# Публичный текст при каждом выпуске

Это обязательная часть выпуска World Clock Widget. Готовить её **до создания тега и публикации установщиков**.

1. Обновить README.md: актуальная версия, обе ссылки скачивания, короткое описание главной пользы и одно-два заметных улучшения. Первый экран репозитория пишется для человека, который видит приложение впервые.
2. Обновить RELEASE_NOTES.md для новой версии. Начать с заголовка «## vX.Y.Z»; этот файл GitHub Actions публикует как текст релиза. Описывать, что стало удобнее и в каком сценарии, а не список внутренних задач.
3. Добавить новую запись в CHANGELOG.md. Если появились новые возможности или изменился пользовательский сценарий, обновить docs/FEATURES.md и краткий встроенный обзор в native/ui/app.js, чтобы оба описания соответствовали выпуску.
4. После публикации сверить страницу GitHub Release, оба файла загрузки, README и ссылки на сайте. Текст релиза должен соответствовать именно приложенным файлам и установленной версии.

## Тон и границы

- Писать понятным языком, с акцентом на пользу и реальные действия: «найти время для звонка», «скопировать местное время», «создать напоминание».
- Не помещать в публичные README, RELEASE_NOTES.md и CHANGELOG.md внутренние результаты сборки, названия тестовых сред, служебные номера задач, причины технических решений и непроверенные обещания. Эти сведения остаются в CURRENT_BASELINE.md и отчёте о проверках.
- Практические шаги установки и системные запросы подтверждения описывать честно и кратко. Ограничения, которые реально влияют на использование, не скрывать.
- Не публиковать шаблонное «MVP-релиз» и не копировать текст прошлой версии без проверки фактических изменений.

Изменение только документации не повышает версию приложения и не требует переустановки.

## Проверка публичного текста перед публикацией

- Описывать только изменения относительно предыдущего опубликованного выпуска. Не выдавать сохранённые возможности прошлой версии за новые.
- Для каждого пункта назвать действие пользователя и результат: что добавлено, улучшено или исправлено. Если исправление одно, достаточно одного короткого пункта в разделе «Исправлено».
- Не рассказывать о переносе хостинга, удалении старых публикаций, переадресациях, ходе отладки и нашей переписке. Для исправленной ссылки достаточно «Исправлено открытие страницы …».
- Главная сайта описывает приложение. Не добавлять туда автоматически заметки о выпуске, технические объяснения или историю исправлений. Номер версии, ссылки скачивания и ссылка на GitHub Release обновляются штатно; отдельный блок «Что нового» — только по прямому запросу пользователя.
- Перед завершением прочитать опубликованный GitHub Release и README как новый пользователь, сверить их с RELEASE_NOTES.md и CHANGELOG.md. Проверить, что текст на русском отображается без повреждённой кодировки.
